# 구현 순서

## PR-A: 기준선과 문서
현재 HEAD 비교, 저장 백업, 빌드 ID 표시, 기준 fixture/화면 확보. MASTER 문서와 기존 AGENTS·디자인 규칙의 충돌을 먼저 제거한다. 게임 기능 변경은 이 단계에서 하지 않는다.

## PR-B: 안전성
PauseCoordinator, 모달 입력, 필터 3분리, 거래/저장 무결성. PAU/FIL/SAV의 P0를 통과시킨다.

## PR-C: 해상도와 공통 UI
PresentationRoot, world640×360/UI1280×720, 토큰, HUD, 모달. LAY 전체 통과.

## PR-D: 장비 작업창
7부위+60칸+상세 비교, 명시적 판매, 잠금, 복구. INV 전체와 시각 golden 검수. 사용자 확인 후 다음으로 간다.

## PR-E: 성장
직업 데이터/초상 일치, 액티브·패시브·런 변형, 환생 보존. CLS/REB 전체 통과.

## PR-F: 회수와 이동
PickupSystem, 원장/표현 분리, 전환 정산, 공통 보행 데이터. LOO/MAP 검증.

## PR-G: 시각 완성
3테마/9방, 아트 카탈로그, 6직업 모션, 도움말/기록/튜토리얼. 미구현은 숨기고 아트 승인 별도.

## PR-H: 종합 검수
전체 케이스 실행, Windows/Web export, 실제 사용자 플레이 확인. 각 PR에 변경 파일, 자동 검증, 캡처, 미검증 항목, 로컬 테스트 명령, 롤백 절차를 적는다. main은 승인 후에만 머지한다.

예상 시간을 근거 없이 약속하지 않는다. 각 단계 범위가 큰 경우 하위 PR로 나누되 명세의 행동/데이터 규칙을 바꾸지 않는다.
