# Stitch 4개 시안의 Unity 구현 판단

검토: 2026-09-26. 사용자 제공 ZIP 4개의 screen.png를 모두 직접 확인하고 code.html 및 공통 DESIGN.md를 조사했다. **4개 화면 모두 Unity 6000.3.24f1 / C# / Built-in 2D에서 구현 가능하다. 이 UI를 위해 엔진·버전·렌더러·패키지를 변경할 필요는 없다.** 구현 가능성 검토이며, 해당 화면의 Unity 구현 완료나 사용자 시각 승인을 뜻하지 않는다.

사용자가 직접 제공한 시안의 화면 구성을 우선 기준으로 삼는다. 앞서 만든 작은 코너 HUD를 유지한 채 색상만 바꾸는 작업으로 대체하지 않는다. 탕탕특공대 성장 선택은 제외한다. 원본 식별과 SHA-256은 [참조 manifest](assets/stitch-reference-manifest.json)에 기록했다. 원본 ZIP·화면은 로컬 ignored Build/Reference/Stitch에 있고 공개 저장소에는 복사하지 않았다.

## 실제 확인한 화면

| ZIP 접미사 | 화면 / 원본 이미지 크기 | 유지할 UI 구조 | Unity에서 연결할 실제 기능 |
|---|---|---|---|
| 없음 | 영웅 선택, 1600×1280 | 왼쪽 영웅 목록, 중앙 선택 인물, 오른쪽 클래스·능력·스킬, 하단 난이도와 입장 | 선택 상태, 캐릭터 데이터·저장, 난이도 적용, 타운 진입 |
| (1) | 던전 전투, 1600×1335 | 상단 지역·웨이브·보스, 우측 미니맵, 하단 좌우 HP/MP 구체와 중앙 스킬바·경험치 | 실제 체력·마나·쿨다운·경험치, 월드 좌표 기반 미니맵, 데미지 피드백, 전리품 |
| (2) | 타운 거점, 1600×1315 | 중앙 포털과 NPC, 우측 퀘스트, 좌측 로그, 하단 전투 공통 HUD | 이동·NPC 상호작용·포털 전환, 퀘스트 상태, 휴식과 전투 입력 구분 |
| (3) | 장비·특성 관리, 1362×1600 | 왼쪽 장착/가방/유물, 오른쪽 특성 노드와 아이템 비교 | 선택·장착·해제·정렬, 비교 수치, 특성 포인트 소비/초기화, 전투 수치 반영 |

두 전투/타운 시안의 중앙 영역은 UI만으로 완성되지 않는다. 실제 캐릭터·맵·공격·NPC는 Unity 월드에서 렌더하고, HUD가 그 위에 놓인다. 웹 시안의 캐릭터 아이콘이나 UI가 통째로 들어간 삽입 그림을 게임 스프라이트로 사용하지 않는다.

## 구현 방식

현재 Packages/packages-lock.json에 com.unity.modules.uielements 1.0.0이 이미 존재하고, 설치된 에디터에 UnityEngine.UIElementsModule.dll이 있다. 이 프로젝트에는 **UI Toolkit의 UXML/USS + C#**를 우선 적용할 수 있다. 이는 Unity 네이티브 런타임 UI이며 HTML을 띄우는 웹뷰가 아니다. 현행 EncounterHud.cs는 OnGUI/IMGUI 방식이므로 새 구조로 교체하는 작업이 필요하다.

- UXML/USS: 공통 상단 메뉴, 패널, 리스트, 가방 슬롯, 탭, 스크롤, 색상·간격·선택 상태.
- C#: 화면 전환, 포커스와 단축키, 장착·특성 명령, 툴팁·비교, 모델 변경에 따른 수치 갱신. 슬롯 드래그는 런타임 pointer capture로 별도 구현한다.
- UI 이미지와 custom drawing: HP/MP 구체의 수위·반사광, 쿨다운 부채꼴, 특성 연결선, 프레임·하이라이트. 브라우저의 gradient/box-shadow를 그대로 붙여 넣는 방식은 쓰지 않는다.
- Unity 2D 월드: 캐릭터 애니메이션, 지형, 충돌, 공격 이펙트, 전리품과 NPC. 미니맵 표시에는 실제 위치 데이터를 사용한다.

uGUI도 가능하지만 현재 manifest에 com.unity.ugui는 없다. 지금 단계에서 추가할 이유는 없다. 화면 공간 HUD와 메뉴를 구현하는 데 URP 전환은 필요하지 않다. 후속 월드의 실시간 조명·그림자는 UI 구현 가능성과 별도로 판단한다.

기술 근거: Unity 6.3 공식 [UI 시스템 비교](https://docs.unity3d.com/6000.3/Documentation/Manual/UI-system-compare.html)는 UI Toolkit을 여러 해상도의 메뉴/HUD에 사용할 수 있는 런타임 선택지로 설명한다. [USS 속성 목록](https://docs.unity3d.com/6000.3/Documentation/Manual/UIE-USS-Properties-Reference.html)을 기준으로 웹 스타일을 Unity 스타일과 이미지 부품으로 재구성한다. 브라우저 CSS 전체와의 호환성을 가정하지 않는다.

## 원본에서 그대로 실행되지 않는 부분

각 ZIP에는 code.html, screen.png, DESIGN.md만 있다. 4개 DESIGN.md의 해시는 동일하다. HTML은 Tailwind CDN, Google Fonts, Material Symbols, 일부 원격 이미지를 사용한다. PNG는 합쳐진 화면이며 독립적인 프레임·슬롯·아이콘·애니메이션 에셋 묶음이 아니다.

영웅 선택에는 목록 선택 강조와 입장 버튼 눌림 연출이 있고, 장비 화면에는 일부 알림·저장 문구 변경·슬롯 강조가 있다. 이것이 캐릭터 생성/저장, 실제 장착, 특성 계산, 타운 전환을 구현한 것은 아니다. 대부분의 상단 이동 링크는 #이며 서로 연결된 게임 화면이 아니다. 표시된 DPS·재화·서버 지연·FPS 등도 게임 실측 데이터로 취급하지 않는다.

따라서 레이아웃·색상·기능 흐름은 설계 기준으로 재사용하고, 게임 로직과 화면 연결은 C#으로 구현한다. 원격 이미지의 URL만으로 게임 사용/공개 배포 권한을 확정하지 않는다. 필요한 인물·장비·스킬·프레임은 무료 라이선스가 확인된 원본 또는 직접 제작 에셋으로 채운다. 폰트 원본도 ZIP에 없으므로 영문과 한글을 함께 검수해야 한다. 일부 JS 알림 문자열에는 이미 문자가 손상된 부분이 있어 그대로 복사하지 않는다.

## PC 가로 화면으로 옮길 때

네 스크린샷 모두 16:9 고정 게임 화면이 아니다. 특히 장비 시안은 1362×1600의 긴 페이지다. 이를 1920×1080 화면에 통째로 축소하면 글자와 슬롯이 작아져 사용성이 떨어진다.

기본 검수 해상도는 1920×1080, 보조 검수는 1280×720으로 둔다. 상단 탐색과 하단 구체/핫바는 화면 가장자리에 고정하고 전장은 남은 공간을 채운다. 영웅 선택의 목록·인물·설명 3영역, 장비의 왼쪽 장착/가방과 오른쪽 특성/비교 관계를 유지한다. 넘치는 목록과 관리 영역은 각각 스크롤하며 페이지 전체를 축소하지 않는다. 유물/특성 영역의 작은 해상도 탭 전환은 필요할 때만 적용한다.

DESIGN.md는 각진 고딕 픽셀 UI를 말하지만 일부 실제 화면에는 둥근 카드·부드러운 발광이 있다. 장식 규칙을 기계적으로 적용해 사용자가 제공한 화면을 다시 바꾸지 않는다. 실제 screen.png의 배치와 정보 위계를 먼저 구현하고, 새 에셋의 질감은 해당 화면에서 함께 비교한다. PC 목표에 불필요한 모바일 전용 레이아웃·상점·온라인 기능을 문서 내용만 보고 확장하지 않는다.

## 구현 순서와 통과 기준

1. 전투 화면의 상단/우측/하단 구성을 네이티브 UI로 옮기고, 기존 1대1 전투의 실제 HP·공격·보상을 연결한다. 없는 마나/스킬을 가짜 작동 상태로 표시하지 않는다. 두 해상도의 실제 Windows 화면을 원본과 비교한다.
2. 장비 선택 → 비교 → 장착 → 수치와 실제 타격 변화, 특성 1분기의 투자/초기화를 연결한다. 고정 수치표만 만든 상태를 인벤토리 완성으로 부르지 않는다.
3. 영웅 선택 → 타운 → 던전 → 타운 → 장비의 전환을 연결한다. 캐릭터 1종과 NPC 최소 기능부터 완성한다.

최초 판단 시점에는 ZIP/화면/소스 검토와 모듈/공식 문서 대조만 완료했다. 이후 사용자의 계속 진행 요청에 따라 **전투 HUD의 첫 네이티브 UI 구현**을 진행했다. 현재는 C# VisualElement로 구성하며 재사용 레이아웃을 UXML/USS로 분리하는 작업은 후속 범위다.
