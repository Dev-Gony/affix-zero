# AFFIX: ZERO — Hero Siege 오마주 목표 UX

작성: 2026-09-26. 상태: **목표 사양 / 구현 완료 아님 / 기존 화면은 사용자 거절**.

최신 사용자 지시는 “탕탕특공대 아예 폐기, 히어로 시즈 오마주, Asset 다시 잡아”다. 이 문서는 그 지시와 사용자가 첨부한 Hero Siege 실전 화면을 기준으로 한다. 이전의 “Hero Siege 코너 배치 + Survivor.io 성장 선택” 결합안은 더 이상 목표가 아니다. **Survivor.io식 레벨업 3지선다, 3장 선택 카드, 모바일 세로 전투 문법은 제외한다.** 기존 문서에 남은 해당 표현은 과거 의사결정 기록이며 최신 제품 방향으로 사용하지 않는다.

이 문서 작성에서는 코드, 씬, 패키지, 이미지, 기존 Godot 자료를 변경하거나 복원하지 않았다. 원작의 화면 구조와 상호작용을 연구하되 원작 이미지·프레임·아이콘·폰트·스킬 이름·지도·수치를 추출해 재사용하지 않는다.

## 2. 첨부 화면이 요구하는 전투의 시각적 관계

### 관찰

- 인물은 화면의 작은 일부다. 중앙 부근 플레이어보다 주변 기둥, 통로, 접근하는 적의 방향, 공격 궤적이 넓은 화면에 함께 보인다. 인물 높이는 화면 높이의 수% 수준으로 보이지만, 첨부가 축소 이미지이고 효과가 겹치므로 정확한 캐릭터 바운딩 박스를 측정한 값으로 사용하지 않는다.
- 영웅 주변 여러 방향에 적이 있고, 투사체와 피격 효과가 공간 관계를 드러낸다. 단순히 두 인물이 마주 선 좌우 레인 장면이 아니다.
- 좌상단은 초상·이름·짧은 상태 막대가 한 덩어리다. 좌하단은 장식된 프레임 안에 작은 그림 아이콘과 키 표기가 밀집한다. 큰 기능 설명 문장은 없다.
- 우상단에는 전장 형태와 점/표식을 가진 미니맵이 있고, 옆의 짧은 지역·난이도 텍스트와 연결된다. 미니맵은 빈 모양 장식이 아니다.
- UI는 화면 끝에 붙어 있다. 모서리 프레임·분리선·아이콘 슬롯의 시각 언어가 통일돼 있으며, 웹 페이지처럼 독립 카드들을 넓게 띄워 배치한 화면이 아니다.

### 해석

중앙의 캐릭터를 크게 보여주는 캐릭터 전시보다, **캐릭터가 어느 공간에서 무엇을 향해 행동하며 어떤 위협을 받는지 읽는 것**이 우선이다. HUD 밀도는 작은 글자를 무조건 많이 쓰는 일이 아니라, 입력 가능한 능력·생존 상태·전리품·탐색 정보를 짧은 거리 안에서 연결하는 방식이다.

### AFFIX 제안

- 실제 새 영웅·적·환경 팩의 픽셀 밀도와 발 기준을 맞춘 뒤 카메라를 잡는다. 캐릭터를 축소하기 위해 스프라이트만 임의로 줄이거나, 주변 공간을 비워서 화면 비율만 흉내 내지 않는다.
- 첫 구도 시안은 영웅의 가시 몸체가 화면 높이 약 3~5%에 들어오는 범위를 비교 출발점으로 삼는다. 이는 원작의 확정 측정치가 아닌 **시안 가설**이다. 720p라면 약 22~36px이며 실제 자세·무기·얼굴 실루엣이 읽히는지 함께 확인한다.
- 캐릭터 발 위치, 무기 궤적, 적 머리 위 HP, 바닥 드랍 라벨이 서로 다른 높이와 레이어를 갖게 한다. 화면 좌표로 고정된 적 HP 카드로 전장 대상을 대신하지 않는다.
- 바닥·벽·장애물·통로의 스케일과 방향성이 먼저 읽혀야 한다. 적 수와 이펙트 개수를 늘려 비어 있는 환경 문제를 가리지 않는다.
- 첨부의 갈색 석조·어두운 가장자리는 관찰 사항이다. 이것을 폐기한 과거 폐허 아트 복원 허가로 해석하지 않는다. 새 팩의 분위기·재질·색 대비를 별도 시각 검수하며, 기존 팩을 재색칠하는 것으로 재선정을 완료 처리하지 않는다.

## 3. 상시 전투 HUD의 역할

| 영역 | 원작 화면 관찰 | AFFIX 목표 기능 | 아직 기능이 없을 때 |
| --- | --- | --- | --- |
| 좌상단 생존 묶음 | 초상, 이름, HP/별도 자원, 작은 단계·상태 아이콘 | 누구의 상태인지 즉시 식별, 현재/최대 HP, 실제 지속 효과를 hover로 설명 | 별도 자원·레벨 시스템 없이 마나/레벨을 그리지 않음 |
| 좌하단 hotbar | 작은 스킬 그림, 키 표기, 소모품/단축 슬롯, 진행 정보와 재화 | 입력·재사용 대기·사용 불가 이유가 같은 아이콘에서 연결됨. hover로 기능/피해/비용/쿨다운 확인 | 장식용 빈 8슬롯을 채우지 않고 구현된 능력만 둠 |
| 우상단 탐색 묶음 | 미니맵, 지역·난이도, 상황에 따른 퀘스트 | 실제 지형과 플레이어 위치, 관측 가능한 출입구/대상 표시. 월드와 좌표 일치 | 기능 없는 가짜 미니맵을 표시하지 않음. 최종 목표에서 빠진 것으로 기록 |
| 전장 대상 | 적 머리 위 짧은 HP, 대상 이름, 드랍 이름 | 정보를 해당 월드 대상에 붙이고 겹침 시 우선순위를 적용 | 일반 적을 모두 큰 고정 카드로 확대하지 않음 |
| 상황성 정보 | 공격 이펙트·드랍·효과가 전투 위치에 나타남 | 실제 수령/피해 이벤트만 표시하고 짧게 소멸 | 연출의 수명으로 보상/피해를 다시 지급하지 않음 |

**같은 모서리에 놓는 것만으로는 이 UX를 구현한 것이 아니다.** 지금의 AUTO ATTACK 문구와 시간 막대는 AI 상태를 알려줄 뿐, 선택 가능한 능력의 hotbar가 아니다. 앞으로 hotbar를 만들 때는 `입력 → 실행 조건 → 동작 → 피해/효과 → 쿨다운 → 다시 사용 가능`이 실제 데이터로 이어져야 한다.

프레임은 새 아트의 재질과 동일한 문법을 갖춘다. 픽셀 테두리 두께, 모서리, 슬롯의 눌림·hover·선택 상태, 글자 대비를 한 세트로 검수한다. 원작의 장식 프레임을 잘라 쓰거나 단색 사각형 위치만 맞춘 것을 아트 완성으로 취급하지 않는다. 실제 조작 가능한 상태에만 강조·잠금·수량을 표시한다.

## 4. 장비 UX는 숫자 열람창과 다르다

### 현재 CHARACTER 창에 있는 것

영웅과 고정 무기 그림, HP, 공격력, 방어력, 공격 시간이다. 이는 현재 액터 상태의 읽기 전용 요약이다. 잘못된 수치를 표시한다는 뜻은 아니지만 **장비를 판단하고 바꾸는 경험은 없다.**

### 빠진 의사결정과 상태

| 사용자가 해야 할 일 | 현재 없는 연결 | 목표 피드백 |
| --- | --- | --- |
| 새 아이템을 발견한다 | 드랍 아이템 인스턴스·이름·아이콘·획득 대상 | 필드 라벨과 동일 아이템이 가방에 들어옴 |
| 내가 가진 것인지 확인한다 | 소지 아이템 목록/격자와 획득 상태 | 소지 위치, 수량 또는 개체 구분, 장착 여부 |
| 어느 부위에 쓰는지 안다 | 슬롯 유형, 장착 대상, 요구 조건 | 호환 슬롯·장착 가능/불가 이유 |
| 지금 무기와 비교한다 | 현재 장비와 후보의 두 데이터 집합 | 기본 성능·옵션·요구 조건을 같은 항목 순서로 비교 |
| 교체를 결정한다 | 장착/해제 트랜잭션과 이전 장비 반환 | 새 장착 표시, 가방 변경, 변경 수치의 즉시 반영 |
| 달라진 전투를 확인한다 | 아이템 데이터에서 전투 동작/능력으로 이어지는 경로 | 다음 공격에서 실제 피해·속도·범위 등 선택 결과를 체감 |

장비창의 최소 성공 조건은 “검 그림과 공격력 30이 보인다”가 아니다. **드랍한 후보를 현재 장비와 비교하고, 교체한 뒤 실제 다음 공격이 바뀌며, 다시 열었을 때 같은 장착 상태가 보이는 것**이다.

### 장비·인벤토리 화면의 목표

오른쪽에 여는 별도 창을 기본 후보로 삼는다. 위쪽은 실제 장착 부위, 아래쪽은 실제 소지품, 후보 툴팁은 선택한 아이템 가까이에 둔다. 격자와 슬롯 수는 새 시스템 규모에 맞춰 정하고, 원작의 Charms·성물·여러 가방 탭 수를 처음부터 복제하지 않는다.

툴팁 정보 순서는 `이름/등급 → 아이템 종류·부위 → 기본 성능 → 실제 옵션 → 요구 조건 → 가능한 입력`이다. 한 수치만 초록색으로 만들며 모든 후보를 “더 좋음”으로 판정하지 않는다. 피해·공격 주기·방어·행동 변경은 서로 다른 선택이며 비교는 같은 단위와 조건을 사용한다. 색은 이름·부호·항목명과 함께 써서 색상만으로 의미를 전달하지 않는다.

공식 스크린샷 아래에는 LMB 집기, RMB 장착/사용, Shift 비교, Alt 검사, 조합키 드랍·스택 분리 안내가 보인다. 이것은 **화면에서 읽은 입력 안내**이며 직접 눌러 본 결과는 아니다. AFFIX는 실제로 지원하는 동작만 안내하며 같은 키 체계를 사용할지는 입력 설계에서 결정한다.

## 5. 스킬 트리와 hotbar를 잇는 성장 경험

공식 스킬 화면은 노드 연결선, 분야별 탭, 사용할 포인트, 노드의 효과 툴팁, 확정/초기화 버튼을 보여준다. 공식 설명도 스킬과 하위 변경을 통한 빌드 구성을 말한다. 따라서 AFFIX의 성장 UX 목표는 전투 중 임의의 세 카드를 받는 방식이 아니라, **내 빌드를 열어 연결 관계와 조건을 보고 배분하는 방식**이다.

목표 흐름은 다음과 같다.

1. 실제 획득한 성장 자원이 있다면 HUD에 미사용 자원 알림을 표시한다.
2. 별도 스킬 창에서 현재 배분·선행 조건·선택 가능한 노드를 구분한다.
3. hover 또는 선택으로 현재 효과와 다음 단계 효과, 소모 포인트를 비교한다.
4. 사용자 확정으로 실제 자원을 소비하고 배분 결과를 저장할 상태에 반영한다.
5. 새 액티브 능력은 hotbar에 배치되고, 패시브/변형은 실제 공격 동작이나 결과에 적용된다.
6. 창을 닫고 같은 전장에서 변화가 확인된다.

초기 목표는 거대한 노드 숲이 아니다. 기본 공격 1개와 그 공격을 의미 있게 바꾸는 작은 분기만으로 `선택 → 배분 → 실행 변화`를 증명한다. 수백 개의 잠긴 노드나 눌러도 아무 일 없는 스킬 그림으로 원작의 밀도를 흉내 내지 않는다. 재분배·비용·영구 저장은 규칙을 정하고 검증한 경우에만 UI에 노출한다.

## 6. 입력과 화면 전환 계약 — AFFIX 제안

아래는 원작의 전체 키 매핑을 복제한 표가 아니라 AFFIX에 필요한 **입력 역할**이다. 구체 키 배정은 바인딩표와 함께 하나의 기준으로 확정해야 한다.

| 입력 상태 | 해야 할 일 | 방지할 오류 |
| --- | --- | --- |
| 전투 | 이동/대상 지정/가능한 액티브 사용 또는 자동전투 제어 | UI를 클릭했는데 뒤의 적도 공격됨 |
| 아이콘 hover | 해당 능력·아이템의 상세, 조건, 현재 상태 확인 | hover만으로 소비·장착·포인트 배분 발생 |
| 인벤토리 열림 | 후보 선택, 비교, 장착, 장착 후 상태 확인 | 가방 아이템과 실제 장비가 불일치, 교체한 이전 아이템 소실 |
| 스킬 창 열림 | 노드 탐색·조건 확인·배분 확정 | 선택만 했는데 포인트가 소모됨, 적용 없이 표시만 변경 |
| 툴팁/창 닫기 | Esc는 가장 위의 상태부터 닫고 전투로 복귀 | 창 닫기와 전체 일시정지가 동시에 토글됨 |
| 일시정지 | 사용자 pause와 창 때문에 생긴 pause 이유를 분리 | 창을 닫았더니 사용자가 멈춘 게임이 자동 재개됨 |
| 재시작/새 구간 | 임시 전투 상태 초기화 범위가 분명함 | 이전 공격·드랍·보상 이벤트가 새 상태에 도착해 중복 적용 |

원작 이미지에서는 캐릭터창이 열린 동안에도 월드가 보이지만, **이미지만으로 시간이 계속 흐르는지 멈추는지 판단할 수 없다.** AFFIX의 창 개방 시 pause 정책은 명시적으로 정한다. 현재 구현의 pause 동작이 원작을 재현한다고 주장하지 않는다.

기존 방치형 의도가 최신 지시에서 철회됐다고 임의로 단정하지 않는다. 다만 자동사냥을 유지하더라도 장비·스킬 판단까지 읽기 전용 숫자로 축소하지 않는다. 자동/수동 전투의 비중은 최신 제품 문서에서 일관되게 확정하고, 어느 방식이든 전투 데이터와 사용자의 빌드 선택은 연결돼야 한다.

## 7. 새 에셋을 평가할 UX 조건

- 영웅과 적은 서로 다른 실루엣·몸 비율·행동으로 읽혀야 한다. 같은 NinjaGreen을 색과 무기만 바꾼 조합을 목표 몬스터 아트로 유지하지 않는다.
- 몸·무기의 실제 idle/walk/attack/hit/death와 필요한 방향이 있어야 한다. 멀리서 작은 몸체로 볼 때에도 준비/impact/회복을 구분할 수 있는지 실제 배율로 검수한다.
- 아이콘은 휘두르는 무기 프레임과 별개의 읽기 쉬운 인벤토리 실루엣이 필요하다. UI 축소 크기에서도 무기·방어구·소모품의 종류가 구별돼야 한다.
- 환경은 바닥 하나와 큰 장식 몇 개가 아니라 이동 가능한 면·장애물·경계·문/통로를 구성할 수 있어야 한다. 미니맵에 표시할 실제 구조도 여기서 나온다.
- UI 테두리·슬롯·선택 상태·글꼴은 새 월드와 픽셀 밀도/명암/재질이 맞아야 한다. 제작자 원본과 정확한 라이선스·공개 재배포 권리를 먼저 확인한다.
- 원작 스크린샷은 관찰 자료다. 원작 스크린샷을 잘라 자산으로 만들거나 새 에셋의 생성 입력으로 사용하지 않는다.

## 8. 구현을 재개하기 전과 다음 최소 단면

**지금 필요한 것은 또 다른 코너 배치 수정이 아니다.** 먼저 새 아트 후보를 실제 목표 배율로 놓은 전장 구성, 같은 아트 문법의 HUD, 장비 비교/장착 상태와 스킬 배분 상태를 하나의 화면군으로 검토한다. 이 검토에서 정적인 시안·실제 동작·승인 여부를 구분한다.

목표를 검증할 다음 최소 단면은 `영웅 1 + 별도 적 1 + 실제 방향/타격 → 아이템 후보 1개 획득 → 현재 무기와 비교 → 장착 교체 → 다음 공격 변화`다. 이 단면에 필요한 작은 인벤토리와 툴팁은 만들되, 대규모 아이템 풀·거래소·시즌·다수 직업·펫·대량 웨이브로 확장하지 않는다. 스킬은 이후 동일 단면에서 작은 분기 1개를 배분하고 실행 변화를 확인한다. 두 흐름 모두 이 문서에서는 **계획**이다.

실제 지형/위치 기반 미니맵과 기능이 있는 hotbar는 최종 전투 화면의 목표다. 첫 검토에서 빠져 있다면 “없음/미구현”으로 기록하며 장식으로 채워 완성이라고 하지 않는다. 화면군이 원작 오마주로 읽히는지에 대한 사용자 시각 승인을 단순 HP·보상 테스트 PASS로 대체하지 않는다.
