# ART-RESET-01 트러블슈팅

| 문제 발생 지점 | 원인 분석 | 해결 방법 및 적용된 코드 개념 | 배운 점 |
| --- | --- | --- | --- |
| 거절된 시각 자료가 다음 개발에도 반복 사용됨 | 기존 아틀라스를 본게임 자산이라 부르며 새로운 레퍼런스 선정 대신 재사용했고 명세가 과거 분위기를 계속 권장함 | 기존 이미지 디렉터리 실제 삭제, design-system 삭제, 현행 AGENTS/HANDOFF 교체, Git blob 기반 재반입 감사 추가 | 코드 재사용 가치와 사용자가 폐기한 시각 자산의 가치는 분리해야 한다 |
| 삭제한 아트가 preload 실패로 이어질 위험 | 기존 룰과 화면 코드가 같은 파일/프로젝트에서 초기화됨 | 규칙 소스는 바이트 보존하고 .gdignore로 과거 렌더를 차단, 양 프로젝트 시작을 이미지 없는 교체 안내로 변경 | 삭제 작업은 파일 제거뿐 아니라 시작 경로와 테스트 계약을 함께 정리해야 한다 |
| 무료 외부 팩의 공개 저장소 업로드 위험 | 상업 사용 가능과 원본 재배포 가능을 같은 권한으로 오인할 수 있음 | 제작자 라이선스를 비교하고 현행 Tiny Swords/CraftPix는 공개 반입 보류. 정확한 CC0 구버전/CC0 대안은 원본 ZIP 검수 후 사용 | 가격이 아니라 파일별 라이선스와 배포 형태를 확인해야 한다 |
| 원본 리소스 다운로드 | 작업 컨테이너의 GitHub DNS 실패와 Kenney ZIP download 실패 | 연결된 GitHub 도구로 삭제/문서를 작업하되 신규 ZIP 반입은 미완료로 기록하고 원본 제공을 요청 | 페이지를 조사한 것과 실제 파일을 확보한 것을 구분해야 한다 |

이 기록은 기존 문제 이력을 삭제하지 않는다. 예전 TROUBLESHOOTING.md는 과거 기록이며 새 아트 복원 지침으로 사용하지 않는다.
