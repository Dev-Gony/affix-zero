# E0 엔진 결정 게이트

상태: 사용자 로컬 환경 확인, 최소 장면 승인 기준 작성. 실제 백업/시험 장면/엔진 비교/성능은 NOT_RUN이다. 사용자 프로젝트를 변환하지 않는다. 구체적인 시험 계약은 E0_ACCEPTANCE.md를 읽는다.

## 변경하지 않는 방향

자동 목표 선택과 접근, 공격 준비 -> 발동 -> 회복, 실제 투사체 충돌, 피격/사망, 중복 없는 보상 이벤트를 검증한다. 수동 회피를 필수 조작으로 추가하지 않는다. 2D 다크 판타지 픽셀 표현과 Windows 첫 검증을 기준으로 준비하되 출시 플랫폼 확정 사실로 취급하지 않는다.

첫 장면은 캐릭터 1종, 근접 적 1종, 원거리 적 1종, 작은 타일 공간, 근접 공격/투사체/드랍 각 1종이다. 펫·가챠·환생·시즌은 넣지 않는다. 실제 프레임 또는 승인된 리깅을 사용한다. 프레임 없이 도형으로 품질 통과를 대체하지 않는다.

## 동일 조건 비교

기본 품질은 1+2 전투 장면으로 확인한다. 부하 검증은 40적, 150/300적을 구분한다. x1/x2/x5는 별도 결과로 기록한다. 워밍업 10초, 측정 60초, 3회 반복이 시험 기준이다. 40적 x1의 p95 16.7ms 이하/p99 33.3ms 이하 목표는 달성 사실이 아니다.

같은 파일 해시의 에셋, 해상도, 위치/스폰 일정, 공격 계약, 효과 수, release 빌드 조건으로 비교한다. 엔진마다 RNG 구현이 달라질 수 있으므로 같은 숫자 seed만으로 동일 전투라고 주장하지 말고 미리 정한 입력/스폰 fixture를 사용한다. 사용자 Windows export와 CI 소프트웨어 렌더를 혼합하지 않는다.

코드 SHA, 엔진 전체 버전, renderer, vsync, fps 제한, 해상도, 모니터 주사율, 활성 객체 수, 원시 프레임 간격 로그를 함께 남긴다. x2/x5는 시뮬레이션 시간 배율이지 벽시계 측정 시간 배율이 아니다. 애니메이션/판정을 빼고 더 빠르다고 보고하지 않는다. 드로우콜/객체 수는 진단 지표이지 엔진간 단독 우열 기준이 아니다.

## 결정 조건

지원 Godot에서 표현/제작/성능/배포가 통과하면 유지 또는 버전 이전을 선택할 수 있다. 필수 아트/플랫폼 연동 부재, 검증된 엔진 병목, 반복적인 로컬 재현 실패가 있고 대안이 통과하면 Unity 등으로 전환한다. 원화 부족과 비효율적인 게임 코드를 엔진 한계로 오인하지 않는다. 기존 코드 보존을 이유로 잘못된 구조를 고수하지도 않는다.

E0-02는 전체 게임 두 개를 병행 제작하지 않는 작은 검증이다. E0-03에서 선택 엔진/버전/실측 근거/남은 위험/필수 로컬 설치/데이터 이전·롤백 계획을 남긴다. 그 뒤 MVP-A로 간다. 자산을 아직 확보하지 않았으면 BLOCKED_ASSET로 분리하며 목업을 승인된 게임 아트라고 보고하지 않는다.
