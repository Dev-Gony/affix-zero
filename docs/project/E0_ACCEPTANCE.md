# E0 최소 전투·에셋·엔진 시험 계약 v0.1

작성: 2026-09-26 KST. 상태: 시험 사양 작성, 아직 게임 구현/실측 아님. 사용자 Backup 실행 확인 전 기존 프로젝트에 통합하거나 새 엔진으로 변환하지 않는다. 이 문서는 첫 시험의 범위이며 완제품 콘텐츠 승인이 아니다.

## 1. 이번에 증명할 장면

캐릭터가 스스로 목표를 고른다 -> 걸어 접근한다 -> 몸과 무기가 함께 공격한다 -> 타격 시점에 피해가 한 번 적용된다 -> 몬스터가 반응하고 죽는다 -> 드랍이 나타나고 캐릭터에게 회수된다.

한 장면에 플레이어 전사 1종, 근접 몬스터 1종, 투사체를 쏘는 원거리 몬스터 1종, 작은 타일 방과 드랍 1종만 둔다. 첫 확인에는 몬스터 각 1마리다. 기능 확인 뒤 같은 개체를 늘려 부하를 시험한다. 펫, 소환, 인벤토리 창, 환생, 레벨업 선택, 상점, 시즌은 넣지 않는다. 배경 꾸미기보다 동작·판정·보상이 우선이다.

## 2. 원본과 시험의 격리

- 원본 로컬 브랜치/기존 저장/15개 stash는 보존한다. 새 장면을 기존 main.tscn에 연결하지 않는다.
- 계획된 시험 경로는 별도 작업 폴더 안의 `experiments/e0-godot/project.godot`이다. 이 경로는 현재 구현된 파일이 아니다. 실제 생성/검증 전 실행을 지시하지 않는다.
- 시험 프로젝트는 고유한 사용자 데이터 식별자 `AFFIX_ZERO_E0`를 사용하고 기존 SaveManager/자동 로드/마이그레이션을 포함하지 않는다.
- 최초 장면에는 영구 저장과 기존 JSON 읽기 자체가 없다. 드랍은 시험 메모리 원장에만 반영한다. 로그도 명시적인 시험 출력 폴더에만 쓴다.
- 후보 엔진별 프로젝트는 같은 중립적인 에셋/스폰 fixture/공격 계약을 사용한다. 기존 게임 리소스를 암묵적으로 로드하지 않는다.
- 테스트가 끝나도 원본 저장을 자동 복원하거나 실험 데이터를 본 게임으로 합치지 않는다.

## 3. 공격과 행동 계약

플레이어 상태는 IDLE, APPROACH, WINDUP, ACTIVE, RECOVERY, DEAD로 구분한다. 목표와 공격 인스턴스 ID를 분리한다. 피해는 ACTIVE 진입 시 한 번, 또는 명시적인 유효 판정 구간 안에서 대상당 한 번만 발생한다. 애니메이션은 해당 상태와 같은 시간 기준을 사용한다. 무기 장면과 피해 타이머가 따로 노는 구현은 불합격이다.

공격을 시작할 때 대상 ID/방향을 기록한다. 타격 시 살아 있는지와 실제 거리를 재검사한다. 타격 전 대상 사망·방 초기화·플레이어 사망은 공격을 취소하고 오래된 타이머가 다른 적에게 피해를 주지 않는다. 목표가 계속 가까운 적으로 바뀌더라도 진행 중인 공격의 무기가 순간이동하지 않는다.

근접 적은 접근/공격/회복, 원거리 적은 거리 확보/예고/발사/회복을 가진다. 발사 시 즉시 피해를 주지 않는다. 투사체는 이전 위치부터 새 위치까지의 이동 구간을 판정해 빠른 속도에서 적을 관통하지 않게 하고, 첫 충돌 뒤 중복 피해를 금지한다. 장애물 관통 정책은 시험 중 고정하고 양 엔진이 같아야 한다.

한 번의 사망은 한 번의 보상 이벤트만 발생시킨다. 소유권은 드랍 그림의 생존 시간이나 회수 애니메이션 콜백에 종속되지 않는다. 실제 보상 전환점은 드랍 접촉으로 정하되 화면 효과가 꺼져도 같은 원장 결과여야 한다.

## 4. 에셋 승인 기준

각 플레이어/적에 idle, walk, attack 또는 cast, hit, death 클립을 명시한다. 실제로 필요한 방향 수, 좌우 반전 허용, 프레임 순서, 반복 여부, fps, 발 기준 pivot, hit 프레임과 무기 포함 여부를 매니페스트에 기록한다. sprite atlas 한 장이라는 사실만으로 다중 프레임이라고 판단하지 않는다.

최초 후보는 몸+무기 일체형 전사다. 이미 검이 그려진 프레임 위에 별도 검을 더하지 않는다. 공격 중 손/몸/무기 관계가 유지되는지, 근접/원거리 적이 정지 원화를 흔드는 것인지 실제 동작인지 각각 확인한다. 추후 무기 외형 교체를 위해 분리형이 필요해지면 독립적인 제작 시험을 한다.

아트는 동일한 픽셀 밀도/바닥 기준/광원 방향/외곽선 수준으로 선택한다. 고해상도 일러스트 한 장을 축소·회전·찌그러뜨린 결과를 최종 애니메이션으로 통과시키지 않는다. 프로토타입용 대체 자산은 화면과 보고서에 명시하고 별도 자산 승인 전 PASS_ART를 부여하지 않는다.

원본 출처 URL, 제작자, 정확한 라이선스, 상업 사용/재배포 범위, 수정 내역, 파일 해시를 기록한다. 공개 GitHub에 올려도 되는 자산인지 반드시 구분한다. 유료 원본을 구매할 필요가 생기면 실제 사용/재배포 조건과 사용자 구매 작업을 먼저 알린다. Hero Siege/Survivor.io 원본 캐릭터나 추출 리소스를 사용하지 않는다. 이번 문서 작성에서 새 에셋을 다운로드하거나 구매했다고 주장하지 않는다.

## 5. 기능 통과 조건

아래 항목은 모두 NOT_RUN으로 시작한다. 테스트와 영상이 생긴 항목에만 결과를 쓴다.

| ID | 재현 절차 | 통과 기준 |
| --- | --- | --- |
| E0-F01 | 입력 없이 플레이어와 근접 적 배치 | 자율 접근 후 공격, 겹친 상태에서 제자리 진동/끝없는 목표 변경 없음 |
| E0-F02 | 공격을 프레임별 관찰 | 준비 중 피해 0, 실제 발동에 피해 1회, 몸/무기/방향/타격 일치 |
| E0-F03 | 준비 중 목표 제거/방 초기화 | 취소된 공격에서 이후 피해와 유령 드랍이 나오지 않음 |
| E0-F04 | 원거리 적이 플레이어에게 발사 | 도착 전 피해 0, 첫 유효 충돌에 피해 1회, 빠른 이동에서도 판정 누락 없음 |
| E0-F05 | 치명 피해와 연속 충돌을 같은 순간 입력 | 적 1개당 사망 1회, 드랍 원장 1개, 반복 획득 없음 |
| E0-F06 | 드랍 시각효과를 제거한 뒤 회수 판정 | 원장과 회수 결과가 효과 존재 여부에 따라 사라지지 않음 |
| E0-F07 | walk/attack/hit/death를 나란히 관찰 | 실제 동작 클립과 바닥 pivot 확인, 부위 겹침/추가 도형 검 없음 |
| E0-F08 | 일시정지 5초 후 재개 | 전투/투사체/스폰/보상 시뮬레이션 정지, 재개 시 몰아서 공격하지 않음 |
| E0-F09 | x1/x2/x5 전환과 벽시계 기록 | 속도 전환이 피해/드랍 중복을 만들지 않고 측정 시간 자체를 배속하지 않음 |
| E0-F10 | 시험 시작 전후 원본 저장 파일 해시 비교 | 원본 저장 읽기/쓰기 경로 없음, 해시 변화 없음; 실제 로컬 검사는 사용자 백업 확인 뒤 수행 |
| E0-F11 | 양 엔진에 같은 스폰·위치·공격 입력 적용 | 입력/자산 해시 일치. 다른 RNG 구현을 같은 seed 숫자로 얼버무리지 않음 |
| E0-F12 | 독립 Windows 실행 파일 시작·종료·재시작 | 미등록 리소스/개발자 절대 경로 의존 없이 시작, 에디터 연결 불필요 |

프레임 애니메이션, 사용자가 느끼는 타격감, 자동검사 통과는 서로 다른 결과다. 헤드리스 테스트로 E0-F07의 시각 승인을 선언하지 않는다.

## 6. 부하 시험 조건

첫 화면은 world 640x360, 표시 1280x720, 정수 2배 확대를 시험값으로 고정한다. legacy 프로젝트 해상도는 바꾸지 않는다. 사용자 장비는 Ryzen 7 5700X/GTX1050/31.9 GiB/Windows 10이다. 이 PC를 전체 출시 최소사양으로 단정하지 않는다.

대표 장면 40적 x1부터 시작한다. 150적/300적은 확장 가능성 탐색이며 실패했다고 즉시 엔진 전환 결론을 내리지 않는다. 각 조건별 warm-up 10초, wall-clock 측정 60초, 3회 반복을 수행한다. x2/x5는 별도 표로 남긴다.

프레임 간격의 p50/p95/p99, 최대 중단, 평균 fps, 적/투사체/효과/드랍 수, 메모리 관측값을 기록한다. p95 16.7ms, p99 33.3ms 이하가 40적 x1의 제안 목표다. 보고하는 값은 달성 결과가 아닌 목표이며 vsync/fps cap/렌더 설정/모니터 주사율을 함께 남긴다. 시간은 단조 증가 벽시계를 사용하고 pause/스폰 준비 시간을 제외하는 규칙을 양 엔진에 동일 적용한다.

프레임 원시 로그는 CSV 또는 JSONL, 실행 메타데이터는 JSON으로 보관한다. 적 수와 효과 수를 줄인 실행을 같은 부하의 개선이라고 표시하지 않는다. 스스로 실행하지 않은 로컬 성능 숫자를 만들어 넣지 않는다. CI 소프트웨어 렌더는 렌더 경로 검증용이며 사용자 GPU 성능을 대신하지 않는다.

## 7. 판정과 다음 작업

개별 상태는 NOT_RUN, PASS_AUTO, PASS_RENDER, USER_ACCEPTED, FAIL, BLOCKED_ASSET, BLOCKED_LOCAL_BACKUP으로 나눈다. 전체 완료는 요구 기능/자산/배포/실측과 사용자 승인을 각각 명시해야 한다. 현재는 사양 작성만 완료했고 백업, 자산, 실제 장면과 실측은 아직 완료되지 않았다.

E0-02 첫 작업은 작은 실제 에셋 세트의 출처/동작 검수와 독립 프로젝트 생성이다. 다음은 같은 장면의 전투 상태/보상/기능 검증이며, 그 뒤 사용자 Windows 시각 확인과 부하 측정이다. Godot 4.3을 최종 엔진으로 고정하지 않는다. 지원 Godot 버전과 Unity 대안을 비교할 때 정확한 버전과 필요한 설치를 먼저 기록한다. 테스트 자산 부족은 엔진 한계가 아니며, 필수 도구 연동이나 실측의 명확한 실패는 엔진 전환 근거가 될 수 있다.

통과 뒤에만 MVP-A의 장비/저장과 연결한다. 기존 게임 전체 수리나 미래 가챠/시즌 구현을 E0의 선행 조건으로 늘리지 않는다.
