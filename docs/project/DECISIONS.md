# 결정 기록

## ADR-R0-001: 엔진 고정 해제와 원본 보존

기록일: 2026-09-26 KST. 근거: 사용자는 Godot 사용 이력이 있더라도 게임 구현 요구에 따라 엔진 전환을 감수한다고 명시했고, 개발 마스터 v0.2 다음 작업 진행을 요청했다.

결정: 기존 기능을 더 늘리기 전에 R0로 로컬 상태와 원본 저장을 확인한다. E0에서는 전투 코어/아트 제작 방식을 작게 검증한다. Godot 계열은 우선 검증 후보, Unity는 주요 대안이며 최종 결정은 미정이다. 기존 Godot 4.3은 현 실행본 재현용이지 새 출시 기반 확정이 아니다. 이전 AGENTS의 Godot 4.3 호환 의무는 기존 런타임 유지에 적용하며 신규 코어 엔진 선택을 구속하지 않는다.

비결정: 이 문서로 Unity 이전, 새 에셋 승인, 새 엔진 설치, PR #17 병합, 전체 PRD의 모든 수치 승인을 간주하지 않는다. 12개 본문과 45페이지 개발 마스터 v0.2는 이전 채팅 첨부를 참조한다.

## ADR-R0-002: 작업 중인 폴더에서 안전하게 도구 실행

현재 사용자의 로컬 HEAD와 미커밋/스태시가 미확인이다. 새 도구를 실행하려고 먼저 개발 브랜치를 switch하면 로컬 변경과 충돌할 수 있다.

결정: 처음에는 fetch로 원격 객체만 받은 후 `git show`로 도구 한 파일을 고유 임시 경로에 추출해 실행한다. 작업 폴더의 파일, index, HEAD와 stash는 변경하지 않는다. 도구는 원격 URL 원문·저장 원문·사용자 이름을 보고서에 넣지 않는다. 로컬 변경은 개수로 알리며 백업했다고 주장하지 않는다.

세이브는 사용자가 실제 user:// 폴더를 확인한 뒤 명시적으로 백업한다. 프로젝트 표시 이름에서 저장 경로를 추측하지 않는다. 백업은 외부 새 디렉터리에 원본 바이트를 복사하고 복사 전 원본/복사 후 원본/복사본의 파일 목록과 SHA-256을 비교한다. 의미 검증·복원·마이그레이션은 수행하지 않는다.

대가: 로컬 상태와 실제 경로 확인을 사용자가 한 번 수행해야 한다. 그 대신 실제 소유권과 편집 중 파일을 원격 추정으로 건드리지 않는다.
