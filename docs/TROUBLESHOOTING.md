# 트러블슈팅과 재시작 기록

| 문제 발생 지점 | 원인 분석 | 해결 방법 및 적용된 코드 개념 | 배운 점 |
| --- | --- | --- | --- |
| project.godot 반복 동기화 중단 | 로컬에 수정된 파일과 원격 변경이 겹침. 엔진 결함을 증명한 것은 아님 | 사용자의 기존 구현 전체 폐기 요청에 따라 새 Unity 개발선과 별도 clone을 사용. 기존 폴더에 더 이상 merge를 요구하지 않음 | 개발 도구의 메타데이터 정책과 사용자 작업 경로를 처음부터 정해야 한다 |
| 기존 아트와 구현의 반복 재사용 | 이전 실패한 화면/임시 코드/지침을 새 단계의 기준으로 계속 이어감 | old tree를 재사용하지 않고 새로운 Unity 파일 트리 생성. 기획만 새 문서로 유지 | 이력 보존과 현재 구현 재사용은 구분해야 한다 |
| 검사 통과를 게임 완성처럼 표현 | 코어/렌더/플레이/시각 검수의 의미를 혼합 | 순수 C# 코어 검사, Unity import, 에디터 실행, Windows 플레이, 사용자 시각 승인을 별도 상태로 기록 | PASS는 실제로 실행한 범위까지만 의미한다 |
