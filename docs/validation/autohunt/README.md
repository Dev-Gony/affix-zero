# 자동사냥 실행 근거

`player-720.json`, `player-1080.json`은 실제 Windows 1배속 실행이다. 각 검사에서 시작 한 번, 3구간·3순환·18처치·4개 수거, 사망/재시도 0회, XP450·골드144를 확인한다. 관리 창 중 사냥, 수동 정지/재개, 유효 타격의 시야·impact 프레임, 이동 가능한 셀을 함께 검사한다. 최종 소스는 `source-fingerprint.json`, 빌드는 `windows-build.json`, 무손실 화면 변환 근거는 `screenshots.json`이다.

`safety-deaths.json`, `safety-bag-full.json`은 별도 실패 유도 검사다. 전자는 각 생명 시작의 공격력을 1로 낮춰 실제 2사망/1재시도 후 중단을 확인한다. 후자는 24개 시험 무기로 가방을 채워 실제 드랍을 보존하고 중단하는지 검사한다. 각 중단 상태를 4초 관찰했다. 정상 성능이나 20분 안정성 검사가 아니다. 해당 시점 빌드와 소스는 `safety-build.json`, `safety-source-fingerprint.json`에 보존한다. 이후 변경은 관리 창 위 피해 숫자 숨김과 검사 보고서의 최종 성장 수치 추가다. 전투·경로·보상·안전 중단 코드는 동일하다.

실패도 보존한다.

- `failure-initial-ui.json`: 내부 준비 상태 이후 실제 버튼 활성화를 기다리지 않은 검사 타이밍 문제. 실제 버튼 준비 대기로 수정했다.
- `failure-stagger.json`: 일반 피격이 공격을 계속 취소해 0순환·5재시도, 최종 경로 정체로 실패. 일반 피격과 사망 취소를 분리하고 경로 여유 검사를 수정했다.
- `failure-reward-comparison.json`: 3순환 중 사용자가 장비·특성·강화를 직접 조작했다고 확인했다. 지출 없는 골드144를 기대하는 기준 검사와 조건이 달라졌다. 원본 보고에는 최종 지출 수치가 없어 정확한 금액을 복원하지 않는다. 이후 검사 보고에 실제 XP·골드·공격력·장비·강화·특성 상태를 추가했고 무조작 재검사에서 기준 잔액을 확인했다. 보상 지급 버그로 확정하지 않는다.

코어126 checks와 Unity 빌드는 별도 검증이다. UI 입력은 UI Toolkit ClickEvent이며 OS 입력 자동화가 아니다. 사용자 조작 확인을 정식 물리 입력 기능 검수나 시각 승인으로 바꾸지 않는다. 단일 마당 3구간의 짧은 실행이고 디스크 저장·20분 검증·별도 막힘/안전 중단 후 재개는 남아 있다.
