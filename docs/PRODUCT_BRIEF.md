# AFFIX: ZERO — Hero Siege 오마주

최신 기준: 2026-09-26 사용자 지시. **탕탕특공대 요소 전면 폐기. PC 가로형 Hero Siege UI/UX와 픽셀 ARPG 방향으로 재설계한다.** 과거 혼합안·모바일 세로형·레벨업 3지선다·밝은 초원 고정은 현행 요구가 아니다.

## 제품 목표

작은 영웅과 넓은 전장, 공간을 읽게 하는 지형·적·공격 궤적, 아이콘 중심 HUD, 전리품 비교·장착·어픽스와 스킬 배분이 연결되는 PC 핵앤슬래시 액션 RPG다. 최초 요청의 자동사냥/방치 편의는 별도로 철회되지 않았으므로 보존하되 Hero Siege 화면 위에 자동사냥 설명 패널을 얹는 방식으로 구현하지 않는다. 원작의 이름·아이템·지도·이미지·코드를 복제하지 않는다.

핵심 루프는 전투 → 전리품 획득 → 장비 비교/장착 또는 스킬 배분 → 달라진 전투 행동 → 다음 구간이다. 원정 중 무작위 3지선다 UI는 제외한다.

## 현재 상태

사용자 Stitch ZIP4가 UI 구성의 우선 기준이다. [구현 판단](STITCH_UNITY_ASSESSMENT.md) 이후 전투 HUD의 첫 UI Toolkit 구현과 Windows720/1080 실행 검증을 완료했다. 실제 인벤토리/특성·타운·영웅 선택은 남아 있다. 아래 이전 시제품의 상태와 새 구현의 검증을 구분한다.

Ninja Adventure 영웅/적과 평면 HUD 두 시안 모두 시각 방향에서 거절됐다. 기존 C# 시간표·중복 타격 방지·보상/재시작 검사는 기술 근거로 남지만 제품 승인으로 취급하지 않는다. 새 아트 반입과 첫 전투 HUD 구현은 진행됐지만 전체 화면·상호작용 및 사용자 시각 승인은 완료되지 않았다.

## 우선 검증할 한 장면

1. 신규 라이선스 원본으로 영웅1·적1의 실제 걷기/공격/피격/사망, 발 위치·무기·impact 연결.
2. 질감 있는 던전 공간, 작은 인물과 넓은 시야, 필요한 픽셀 HUD 부품을 함께 놓은 실제 Unity 장면 검토. 사각 텍스트 패널 색/위치 수정으로 대신하지 않는다.
3. 채택된 시각 기준 위에 한 무기 드랍·비교·장착·공격 변화와 한 스킬 분기를 연결한다. 고정 수치표를 장비 시스템으로 부르지 않는다.

여러 적·복잡한 스킬·펫·가챠·시즌을 먼저 늘리지 않는다. 전체 화면/애니메이션 검수 없이 빈 씬, 정지 캐릭터, 가짜 아이콘/미니맵을 완료 처리하지 않는다. 자세한 목표는 [HERO_SIEGE_UX_SPEC](HERO_SIEGE_UX_SPEC.md), 아트는 [ART_DIRECTION](ART_DIRECTION.md)에 둔다.

## 엔진과 자산

Unity 6000.3.24f1 / C# 유지. 현재 Built-in 2D도 변경하지 않았다. 국소 조명·그림자는 실제 새 자산 장면에서 검토하고, URP 2D가 필요한 경우 변경 이유·범위·검증을 사용자에게 먼저 설명한다. 엔진 교체가 잘못된 아트 선택을 해결하지 않는다.

게임 사용 허가와 raw asset 공개 GitHub 배포 허가를 분리한다. 유료/재배포 제한 원본은 공개 저장소에 넣지 않는다. Git에는 허용된 코드·설정·출처·반입 절차를 둔다. 사용자 지시에 따라 유료 구입은 제외하고 무료 라이선스와 직접 제작 에셋으로 진행한다.

## 검증 표기

소스 작성 / 코어 검사 / Unity import / Play / Windows build / 실제 실행 / 사용자 시각 승인을 구분한다. 기존 기술 검사 PASS를 새 Hero Siege 시제품의 검증으로 옮겨 적지 않는다. 과거 Godot 코드·아트는 복원하지 않는다. 새 저장·오프라인 보상·온라인/상점은 아직 범위 밖이다.
