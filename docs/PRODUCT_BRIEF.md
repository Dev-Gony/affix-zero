# AFFIX: ZERO 제품 기획 / PRD v0.2

작성 기준: 사용자의 게임 기획, 아트 전면 폐기, 코드 전면 재시작 및 Unity 전환 결정. 아래의 일정 없는 단계·검증 수치는 새 구현을 위한 제안이며 현재 서비스 실적이 아니다.

## 1. 제품 정의

Hero Siege에서 참고할 것은 장비 파밍·어픽스·빌드의 깊이, Survivor.io에서 참고할 것은 읽기 쉬운 다수 적 전투와 성장 선택이다. AFFIX는 이를 자동사냥 중심의 캐주얼 핵앤슬래시 로그라이크 방치형 게임으로 결합한다. 레퍼런스의 소스/이미지/지도/상표 UI를 복제하지 않는다.

핵심 루프: 자동 이동·전투 → 처치·보상 → 장비/스킬 선택 → 달라진 전투 행동 → 다음 구간. 자동사냥의 편안함과 플레이어 선택이 남는 구조를 함께 검증한다. 수동 이동·회피는 별도 선택 사항이며 첫 1대1 구현의 필수 범위가 아니다.

## 2. 초기 MVP

### U1: 첫 전투 경험

밝은 작은 야외 필드, 영웅1종, 근접 적1종, 실제 idle/walk/attack/hit/death 프레임, 접근·타격·피격·사망·재시작. 이어 XP/Gold 회수까지 연결한다. 현재 코드에는 이동/타격/체력/사망 연결과 씬 제작 도구가 있고, 새 아트·Unity 실행·보상 회수는 아직 완료되지 않았다.

공격은 대상과 방향을 고정한 준비 → impact 1회 → 회복으로 구성한다. 타격 시 생존/거리를 재검사하고 취소·범위 이탈·사망 후 유령 피해를 허용하지 않는다. 애니메이션과 실제 타격은 같은 공격 시간표를 사용한다. 여러 프레임을 건너뛰는 경우를 포함해 한 공격의 피해는 한 번만 인정한다.

U1 수락 조건: 검수된 원본 리소스가 실제 로드됨, 화면에서 걷기·공격 자세가 구분됨, 몸/무기가 함께 움직임, 타격 프레임과 피해가 맞음, 적이 죽고 더 공격하지 않음, 재시작 시 이전 전투 상태가 남지 않음. 로그 PASS와 사용자 시각 승인은 별개다.

### U2: 짧은 원정

U1 승인 후 원거리 적과 비유도 투사체, 소규모 웨이브, 명확한 예고를 가진 엘리트1종, 전투 후 회수/결과를 연결한다. 초기 수량과 3분 내외 길이는 밸런스 가설이다. 화면 겹침/읽기 어려움이 있으면 적 수를 늘리지 않는다.

### U3~U4: 빌드와 파밍

원정 중 3지선다, 행동을 바꾸는 소수 스킬/어픽스, 장비 비교·장착, 새 저장 형식을 연결한다. 임시 원정 강화와 영구 장비·성장은 분리한다. 이전 Godot의 7슬롯·60칸·등급/직업 수는 참고 아이디어이며 새 Unity에서 구현 완료 또는 무조건 고정 사양으로 취급하지 않는다.

## 3. 사용자 경험 기준

기본 게임 화면에 엔진 진단 수치, 테스트 PASS 문구, 개발 단계 이름을 노출하지 않는다. 첫 화면에는 필드·캐릭터·HP·진행 목표를 읽기 쉽게 둔다. 설정·검사·기술 보고서는 에디터 도구로 분리한다. 에셋 미확보 상태에는 실행 준비가 안 됐다고 명시하고 빈 씬을 게임이라고 전달하지 않는다.

아이템은 아이콘 실루엣, 등급 표시, 옵션 설명, 현재 장비 대비 변화가 구분되어야 한다. 스킬은 수치뿐 아니라 공격 범위/대상/주기/시너지가 어떻게 달라지는지 표현한다. 원거리 투사체는 발사와 충돌을 구분한다. 보상은 표시 효과 수명과 분리된 고유 획득 ID를 사용한다.

## 4. 제외 범위

초기에는 계정/온라인 순위/상점/결제/유료 가챠/시즌 운영/오프라인 보상/다국어/대량 콘텐츠를 만들지 않는다. 펫이나 환생이 첫 전투 완성보다 먼저 등장하지 않도록 한다. 성능 측정은 실제 게임 화면을 대표하는 장면이 승인된 다음 진행한다.

## 5. 데이터·확장

전투 상태, 원정 상태, 영구 프로필, 외형 소유권, 시즌 프로필을 장기적으로 분리한다. 현재 U1에는 개인 저장을 읽거나 쓰는 코드가 없다. 예전 세이브를 자동 변환하지 않는다. 새 저장을 도입할 때 버전·원자적 저장·중복 획득·중단 복구를 별도 검증한다.

## 6. 완료 상태 표기

SOURCE_WRITTEN → CORE_TESTED → UNITY_IMPORTED → PLAY_TESTED → VISUAL_ACCEPTED → BUILD_TESTED를 구분한다. 현재 U1은 SOURCE_WRITTEN이며 코어 테스트 결과는 VERIFICATION에 기록한다. 실제 리소스 확보와 Windows 에디터/플레이 검증 전에는 U1을 완료로 표시하지 않는다.
