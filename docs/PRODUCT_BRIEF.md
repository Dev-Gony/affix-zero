# AFFIX: ZERO — Hero Siege 오마주 자동사냥 방치형 RPG

현재 저장 연결: 장비·가방·어픽스·강화·특성·XP·골드·미수거 전리품을 로컬 자동 저장하고 실제 별도 Windows 프로세스에서 복원·사냥 재개를 검증했다. 상세 기준과 최신 결과는 [SAVE_PERSISTENCE.md](SAVE_PERSISTENCE.md), `validation/save/`를 우선한다. 아래 저장 추가 전 보고는 당시 상태이며 전체 MVP 완료를 뜻하지 않는다. 20분 실행·별도 경로 막힘/안전 중단 재개·물리 입력과 사용자 시각 검수는 남아 있다.

최신 기준: 2026-09-26 사용자 지시. **탕탕특공대 요소 전면 폐기. PC 가로형 Hero Siege UI/UX와 픽셀 ARPG 방향으로 재설계한다.** 과거 혼합안·모바일 세로형·레벨업 3지선다·밝은 초원 고정은 현행 요구가 아니다.

## 제품 목표

**주력 플레이는 자동 던전 탐색과 자동사냥이다.** 사용자가 2026-09-26 다시 명확히 했다: 캐릭터가 던전을 알아서 돌아다니며 사냥하는 방치형 게임이고, 나머지 장비·아이템/어픽스·특성/스킬·강화·동행수 등 RPG 시스템과 UI/UX는 Hero Siege를 오마주한다. 자동사냥을 선택적 편의 기능이나 후순위로 취급하지 않는다. 원작의 코드·이미지·이름·수치를 복제하지 않고 AFFIX의 자산과 규칙으로 구현한다.

기본 루프는 **자동 경로 탐색 → 적 탐색/접근 → 자동 공격·스킬 → 자동 전리품 회수 → 다음 방/구간 → 클리어 후 자동 재도전**이다. 플레이어는 사냥할 던전과 빌드, 장비·특성·강화·수거 정책을 결정한다. 매 처치마다 회수/다음 전투 버튼을 눌러야 하는 흐름은 목표가 아니다. 반복 사냥의 진입은 명시적 시작/중지로 제어한다.

일반 피격은 체력과 짧은 flash만 반영하며 공격·이동을 취소하지 않는다. 사망할 때 공격을 취소한다. 연속 두 번 사망하면 자동 중단하고, 가방 포화 시 보류 전리품을 보존한 채 멈춘다. 장비·특성·대장간을 열어도 사냥하며 수동 정지만 전투를 멈춘다. 연속 사망·포화 안전 검사는 PASS다. 별도 경로 막힘과 중단 후 재개 검증은 남아 있다.

Stitch 7개 시안은 위 게임의 관리 UI 기준이다. 새 화면이나 참고 ZIP이 추가됐다고 자동사냥보다 관리 UI 구현을 먼저 확장하지 않는다. 탕탕특공대식 무작위 3지선다와 수동 조작 중심 전투로 방향을 바꾸지 않는다. 오프라인 시간 보상은 실행 중 자동사냥과 별도 기능이다.

## 현재 상태

사용자 Stitch ZIP 총 7개가 UI 구성의 우선 기준이다. [구현 판단](STITCH_UNITY_ASSESSMENT.md) 이후 전투 HUD에 더해 단일 무기 인벤토리/비교/장착과 특성 한 분기를 연결하고 Windows720/1080 실제 실행을 검증했다. 추가 04/06 기준의 전용 특성 상세 화면과 실제 골드를 쓰는 무기 확정 강화도 연결했다. 타운·영웅 선택·펫·저장·능동 스킬은 남아 있다. 아래 이전 시제품의 상태와 새 구현의 검증을 구분한다.

Ninja Adventure 영웅/적과 평면 HUD 두 시안 모두 시각 방향에서 거절됐다. 기존 C# 시간표·중복 타격 방지·보상/재시작 검사는 기술 근거로 남지만 제품 승인으로 취급하지 않는다. 새 아트 반입과 첫 전투 HUD 구현은 진행됐지만 전체 화면·상호작용 및 사용자 시각 승인은 완료되지 않았다.

## MVP 우선순위

현재는 단일 사원 마당 안의 세 구간을 자동으로 순회한다. 적 두 개체를 구간마다 재사용하고, BFS 경로 탐색으로 통행 불가 모서리와 석재 장애물을 피한다. 탐색 → 대상 선택/접근 → 자동 공격 → 자동 수거 → 다음 구간 → 입구 귀환/반복을 연결했다. 세 개의 별도 방이나 절차 생성 던전은 아니다. 아직 저장·장시간 실행·예외 조건 검증이 남아 있어 전체 MVP는 아니다.

1. 최종 빌드에서 기본 수치의 무사망 3순환과 실제 전리품 순증, 메뉴 중 사냥을 확인한다.
2. 연속 실패·막힘·포화 시 보존/중단과 재개를 검사하고 로컬 저장·복원을 연결한다.
3. 20분 무조작 실행과 두 해상도 UI, 재실행 복구를 검증한다.

최종 Windows 자동사냥 실행은 [720p 보고](validation/autohunt/player-720.json)와 [1080p 보고](validation/autohunt/player-1080.json) 모두 PASS다. 실행 ID는 각각 `26b0296dea004e06a40c4a3cfab8caa8`(70.9288초), `23dbebd8a24b4397bca82dce83b771bd`(70.6474초), Build GUID는 `6c03e8d2bc6e457abc31582911701d3d`다. 두 실행 모두 실제 1배속으로 3구간·3순환·18처치·4개 수거, 사망 0회·재시도 0회, XP 450·골드 144를 확인했다. 영웅 HP 120/공격력 30·적 HP 54/공격력 6을 바꾸지 않았다. 메뉴 중 사냥과 수동 정지/재개, UI 콜백 7회·실제 framebuffer 6개도 검사했다. [720p 전투](media/autohunt/720-combat.png) · [1080p 관리 중 사냥](media/autohunt/1080-management.png). 로컬 원본은 `Build/Reports/autohunt-diagnostic-{720,1080}/auto-hunt-smoke.json`이다.

최종 빌드는 `Build/Reports/windows-build.json`의 2026-09-26T06:36:34.0607289Z Succeeded, 오류 0/경고 0이다. 정상 두 해상도는 위 최종 빌드의 근거다. 안전 중단은 아래 명시한 직전 빌드에서 검사했으며 safety-build/source-fingerprint 보고서로 구분한다. 앞선 `autohunt-fixed-720` 후보 실행은 이력으로 구분한다. 이전 `docs/validation/management/`는 관리 기능 시제품의 역사적 근거다. 디스크 저장, 20분 연속 실행, OS 물리 입력 검사, 사용자 시각 승인은 완료되지 않았다.

여러 클래스·펫·대형 스킬 계열·소켓/재련·타운 전체·시즌/가챠를 MVP 전에 확장하지 않는다. 이미 검증한 영웅1/적1의 실제 애니메이션을 기반으로 필요한 소규모 적과 경로를 연결한다. 대량 스폰/성능 확장부터 시작하지 않는다. 상세 기준과 남은 작업은 AUTO_HUNT_MVP.md가 우선한다.

## 엔진과 자산

Unity 6000.3.24f1 / C# 유지. 현재 Built-in 2D도 변경하지 않았다. 국소 조명·그림자는 실제 새 자산 장면에서 검토하고, URP 2D가 필요한 경우 변경 이유·범위·검증을 사용자에게 먼저 설명한다. 엔진 교체가 잘못된 아트 선택을 해결하지 않는다.

게임 사용 허가와 raw asset 공개 GitHub 배포 허가를 분리한다. 유료/재배포 제한 원본은 공개 저장소에 넣지 않는다. Git에는 허용된 코드·설정·출처·반입 절차를 둔다. 사용자 지시에 따라 유료 구입은 제외하고 무료 라이선스와 직접 제작 에셋으로 진행한다.
